## ทำไมถึงสร้างระบบนี้

**ปัญหา:** คลังสินค้ามีหลายคลัง หลายสถานที่ การนับสต็อกแบบเดิมใช้เวลามาก

**ทางแก้:** ระบบเว็บสำหรับ**นับสต็อกออนไลน์พร้อมกันหลายคน หลายสถานที่** ซึ่งให้:
1. **ลดเวลานับ** — พนักงานหลายคนนับพร้อมกัน ข้อมูลรวมศูนย์ที่ Supabase
2. **ตรวจสอบได้** — รู้ว่าใครนับอะไร จำนวนเท่าไร เมื่อไหร่ ที่ตำแหน่งไหน
3. **Match ยอด** — รวมผลนับต่อ SKU เทียบกับยอดก่อนนับ (Book) ว่า ครบ / ขาด / เกิน
4. **ปรับยอดได้** — กรณีคาดว่ายอดผิดพลาด เพิ่ม/ลดยอด แล้วเปลี่ยนสถานะเป็นถูกต้อง

## Workflow การทำงานจริง (ตามที่ admin ใช้)

```
1. เปิดรอบใหม่          cycle_config.html   เลือกคลัง → ปี-เดือน → สถานะเปิด → ช่วงวันนับ → ตั้งชื่อ → สร้างรอบ
2. อัปโหลด Book          cycle_config.html   ไฟล์ Excel ยอดก่อนนับจากคลัง → นำเข้า Book → ระบบผูกข้อมูลเทียบ
3. นับสินค้า             index.html          ชื่อผู้นับ → คลัง (เปิดทีละคลัง กันเลือกผิด) → ตำแหน่ง → SKU → จำนวน
                                             ★ โหมดที่ใช้บ่อยสุด: แบบกลุ่ม (สูงสุด 25 รายการ/ชุด) → ส่งออกข้อมูลกลุ่ม
   (ทางเลือก)            import_counts.html  นำเข้าผลนับจำนวนมากจากไฟล์ Excel รูปแบบชัดเจน ในครั้งเดียว
4. ตรวจสอบความถูกต้อง    audit_check.html    แก้ไข SKU / จำนวน / ตำแหน่ง + ลบรายการ + เทียบตำแหน่งกับ Excel + ประวัติแก้ไข/ลบ
5. ดูภาพรวม + Export     count_search.html   กรอง ชื่อ/คลัง/เดือน/ตำแหน่ง/ผู้นับ → Export Excel
6. Match ยอด             reconcile.html      รวมผลนับต่อ SKU เทียบ Book → ครบ/ขาด/เกิน → ปรับยอดกรณีผิดปกติ
                                             ★ "นับเจอแต่ไม่พบ SKU ใน Excel" → กด "สร้างลง Book" (ยอด 0) เพื่อให้การตรวจครบ 100%
                                               จากนั้นสถานะไปอยู่ที่ "เกิน" (Book 0 แต่นับเจอ) — เป็นพฤติกรรมที่ตั้งใจ
                                             ★ "ยังไม่ได้นับ" → กลับไปนับที่ index หรือ import_counts ก่อน
7. ดูผล                  dashboard.html      สรุปผลรวม
                         live_count_wall.html จอแสดงผลนับสดแบบเรียลไทม์ (จากทั้ง index และ import)
                         book_explorer.html  ย้อนดูว่าแต่ละรอบ import Book อะไรเข้ามาบ้าง
```

**หลักการที่ยึดตลอด (นโยบาย admin):** `inventory_counts` = หลักฐานผลนับ "นับมายังไงเก็บอย่างนั้น" — ระบบห้ามลบ/แก้จำนวนเอง แค่เตือนให้คนมายืนยัน · การปรับยอดทำที่ฝั่ง Book (`stock_adjustments`) เท่านั้น

## ฟีเจอร์หลักรายหน้า (ตามที่ admin ไล่ให้)

- **index**: นาฬิกาเรียลไทม์เวลาไทย · การ์ด "บันทึกแล้ววันนี้ SKU/ชิ้น" · การ์ด "ยังไม่ได้นับ" (กดเข้าไปดูรายการ+ค้นหา+Export) · การ์ด % ที่นับแล้วของ Book · badge เชื่อมต่อ Supabase · ปุ่ม Log ประวัติ · Export Excel/CSV
- **audit_check**: Export Excel ทั้งรอบ · โหลดข้อมูลอ้างอิงใหม่ · ลบรายการที่เลือก (หลายรายการ) · ประวัติการแก้ไข/ลบ (เฉพาะรอบ ไม่ปนรอบอื่น) · ลบแถวที่กดบันทึกซ้ำ (ยืนยัน 2 รอบ) · เทียบตำแหน่ง Excel (ทีละโซน + Template) · สลับ SKU/ตำแหน่ง · แก้ไขตำแหน่ง (ไม่ให้สถานะขึ้นตำแหน่งผิด) · เมนูคลังของรอบที่เปิด · ฟิลเตอร์ ถูกต้อง/ผิดพลาด/ตำแหน่งผิด/ทับซ้อน + ขอบเขตกลุ่ม
- **reconcile**: สถิติรวม · ปรับยอดขาด-เกิน · ยืนยันเป็นถูกต้อง (กรองในตัวว่ารายการไหนปรับแล้ว) · สร้างลง Book

## ข้อเสนอปรับปรุง UX/UI/Flow (จัดลำดับความคุ้มค่า — ยังไม่ได้ลงมือ)

### กลุ่ม 1: ตรงกับ workflow ที่ admin เล่ามากที่สุด
1. **ล็อกคลังในหน้า index ตามรอบที่เปิดอยู่** — admin บอกว่า "เปิดไว้แค่ 1 คลังกันเลือกผิด" แต่ระบบยัง hardcode 3 คลัง + ระบุเอง (`index.html:109-112`) · ถ้า dropdown แสดงเฉพาะคลังของรอบ active จะกันพลาดตรงจุดที่ admin กังวลจริง และตัดตัวเลือก "ระบุเอง" ที่ทำให้ข้อมูลหลุด registry (ISSUES L10) ไปในตัว
2. **เพิ่มปุ่ม Export Excel ใน book_explorer** — ช่องว่างที่ admin ระบุเอง · หน้ามีตาราง+ฟิลเตอร์ครบแล้ว เหลือแค่ปุ่ม (แบบเดียวกับ count_search)
3. **แสดงชื่อรอบ (label) เด่น ๆ ในทุกหน้าที่ผูกรอบ** — ตอนนี้ index มี badge เดือน แต่หน้า audit_check/reconcile ผู้ใช้ต้องอ่านจาก dropdown · แถบ "รอบที่กำลังทำงาน: นับสต็อกประจำเดือน..." ช่วยกันงงเวลาเปิดหลายรอบ/หลายจอ
4. **ปุ่ม "ไปขั้นต่อไป" ตาม workflow 7 ขั้น** — เมนูซ้ายเรียงตามหมวด ไม่ได้เรียงตามลำดับงาน · ผู้ใช้ใหม่ต้องจำเองว่า เปิดรอบ→Book→นับ→ตรวจ→Match · แถบ stepper เล็ก ๆ (1→7) บนหัวแต่ละหน้า หรือลิงก์ "ขั้นถัดไป" ท้ายแต่ละงานจะลดการสอนงาน

### กลุ่ม 2: ลดความเสี่ยงข้อมูล
5. **จำกัดกลุ่ม 25 รายการ — ทำเป็นค่าตั้งได้** — hardcode 2 ที่ (`Js/script.js:914` + `index.html:176`) · ถ้าเพิ่มเป็น 50 ตามหน้างานจริงจะลดจำนวนครั้งที่กดส่ง (แต่ chunk insert ต้องทดสอบ)
6. **แก้ M2** — สถานะ JS (`over`) กับ SQL (`count_only`) ไม่ตรงกันกรณี Book 0 + นับเจอ · เกี่ยวตรง ๆ กับ flow "สร้างลง Book ยอด 0 → ควรไปอยู่ที่เกิน" ที่ admin อธิบาย — ตอนนี้ DB ให้ `count_only` ไม่ใช่ `over` ซึ่ง**ขัดกับความตั้งใจของ admin** → ควรยึดฝั่ง JS แล้วแก้ SQL (กลับทิศจากที่เทส M2 assume ไว้) **ต้องให้ admin ยืนยันก่อน**
7. **แชท: ระบุตัวตนขั้นต่ำ** — ก่อนใช้เป็นช่องทางสั่งงานจริง ควรมีอย่างน้อย station-lock หรือรายชื่อพนักงานให้เลือก (ตอนนี้พิมพ์ชื่อเป็นใครก็ได้)

### กลุ่ม 3: เก็บกวาดภายใน (ไม่กระทบผู้ใช้)
8. ถอดคู่มือ + checkbox "ทุกช่วงเวลา" (แผนพร้อมแล้ว — ดู handoff note)
9. Dead code ชุด 6-9 ที่ค้าง (~435 บรรทัด — ISSUES L1/L2): 6 ฟังก์ชันตายใน reconcile-shared, dead handler ใน audit_check, CSS ตาย ~200 บรรทัดใน style.css
10. `escapeHtml` 5 เวอร์ชัน + connection badge 3 แบบ + fallback รายชื่อคลัง 3 ชุด → รวมเป็นตัวเดียว (ISSUES L3)
